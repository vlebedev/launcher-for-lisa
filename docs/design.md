# Launcher for Lisa — design contract

Agreed on 2026-09-09 with the owner (Vladimir, GitHub `vlebedev`). This is the
source of truth for implementation. Do not widen scope beyond it.

## Goal

A launcher for Elizaveta ("Lisa") on an Omarchy 4.0.2 / Hyprland 0.56 laptop
(MacBookPro8,3, single 1920x1200 display, Chromium is the only browser).
Pressing **F1** or the **brightness-down key** (this Apple keyboard sends
`XF86MonBrightnessDown` for a bare F1 press and `F1` for Fn+F1) opens a native
Omarchy menu listing her school sites. Clicking a row opens the site as a
Chromium app window (`--app=URL`, no address bar) on that site's **fixed
workspace**. If the site is already open, the existing window is focused
instead of starting a second copy. Escape closes the menu; pressing the key
again toggles it.

Convenience only. No lockdown: the full Omarchy desktop stays available.

## Sites (`sites.json`, the single source of truth)

Ordered array of objects `{ "id", "label", "glyph", "url", "workspace" }`.
Workspace 1 stays empty as "home". Initial content, in this order:

| id       | label    | url                                | workspace |
|----------|----------|------------------------------------|-----------|
| klett    | Klett    | https://www.meinklett.ch           | 2 |
| anton    | Anton    | https://anton.app                  | 3 |
| antolin  | Antolin  | https://antolin.westermann.de      | 4 |
| weitblick| Weitblick| https://www.weitblick1-digital.ch  | 5 |
| lmvz     | LMVZ     | https://digital.lmvz.ch            | 6 |

`glyph` is a Nerd Font glyph (the Omarchy menu shows glyphs, not images).
Adding a site = edit `sites.json`, commit, push. Her machine pulls and applies.

Sessions persist through Chromium cookies. The launcher opens plain URLs only.
No credentials or login tokens are ever committed to this repo.

## Repo layout

```
sites.json                      # site list (see above)
bin/lisa-launcher               # bash CLI, all runtime logic
systemd/lisa-launcher-update.service
systemd/lisa-launcher-update.timer
setup/create-account.sh         # one-off, run as root by the owner
docs/idea.txt, docs/design.md
README.md
.gitignore                      # ignores private/
private/                        # gitignored; owner's local copy of login links
```

On Lisa's machine the repo is cloned to `~/.local/share/launcher-for-lisa`
(call this `$REPO`). `bin/lisa-launcher` is symlinked to `~/.local/bin/lisa-launcher`
(Omarchy's bash env-bootstrap adds `~/.local/bin` to PATH). Generated Hyprland
config and systemd units must reference the CLI by absolute path
`$HOME/.local/share/launcher-for-lisa/bin/lisa-launcher`, never rely on PATH.

## `bin/lisa-launcher` subcommands

All idempotent. `REPO` = directory containing the script's parent (`bin/..`).

- `install` — generate and apply per-user config from `sites.json`:
  1. Write `~/.config/omarchy/extensions/omarchy-menu.jsonc` **entirely**
     (overwrite; header comment says it is generated by lisa-launcher from
     `sites.json`). Defines a submenu row id `lisa` (label "Lisa", a glyph)
     with alias `lisa`, and one child row `lisa.<id>` per site with
     `icon`=glyph, `label`, `action`=`<abs path>/lisa-launcher open <id>`.
     Verify against `/usr/share/omarchy/shell/plugins/menu/MenuModel.js` and
     `/usr/share/omarchy/bin/omarchy-menu` how `omarchy-menu toggle <route>`
     resolves a route to a submenu id/alias, and make the route `lisa` work.
     The `lisa` row will also appear on the root SUPER+SPACE menu; that is fine.
  2. Write `~/.config/hypr/lisa-launcher.lua` containing:
     - `o.bind("F1", "Lisa launcher", "<abs>/lisa-launcher menu")`
     - `o.bind("XF86MonBrightnessDown", "Lisa launcher", "<abs>/lisa-launcher menu")`
       (this deliberately overrides Omarchy's brightness-down bind; accepted)
     - one `o.window({ class = "^chrome-<host>__-Default$" }, { workspace = "<n>" })`
       per site, where `<host>` is the URL host as Chromium names app windows
       (observed live: `chrome-web.whatsapp.com__-Default`,
       `chrome-mail.google.com__mail_u_0_-Default` — path segments become
       `_`-joined after `__`; for a bare host URL the class is
       `chrome-<host>__-Default`). Check the Lua rule API in
       `/usr/share/omarchy/default/hypr/apps/*.lua` and `windows.lua` for the
       exact `o.window` signature and whether regex class matching is
       supported; use the form those files use.
     Ensure `~/.config/hypr/hyprland.lua` contains the line
     `require("hypr.lisa-launcher")` (append once, after the other requires;
     the skel file is `/etc/skel/.config/hypr/hyprland.lua`).
  3. Install `systemd/*.service|timer` into `~/.config/systemd/user/` and
     enable the timer **without requiring a running user session**: create the
     `timers.target.wants/` symlink by hand, and additionally run
     `systemctl --user daemon-reload && systemctl --user enable --now` only when
     `XDG_RUNTIME_DIR` exists and `systemctl --user` works. Rationale: the
     account script runs `install` before Lisa has ever logged in.
  4. Symlink `~/.local/bin/lisa-launcher` → `$REPO/bin/lisa-launcher`.
  5. If a Hyprland session is running for this user (`hyprctl` works), run
     `hyprctl reload` and `omarchy-menu refresh`; otherwise skip silently.
- `menu` — `omarchy-menu toggle lisa` (or whatever route form step 1 established).
- `open <id>` — look up the site in `sites.json`; run
  `omarchy-launch-or-focus-webapp "<class-pattern>" "<url>"`. Read
  `/usr/share/omarchy/bin/omarchy-launch-or-focus` first: it matches with
  `test("\\b" + pattern + "\\b"; "i")` on class or title, so pick a pattern
  that matches only this site's app window class (e.g. the host with dots
  escaped) and cannot accidentally match another site or a regular Chromium
  window. The workspace switch happens via the window rule on spawn and via
  focus on an existing window.
- `login <id>` — read `~/.config/lisa-launcher/logins` (mode 600, gitignored,
  format: one `<id><TAB><url>` per line, `#` comments allowed). Open that URL
  with `omarchy-launch-webapp "<url>"` so cookies land in the same Chromium
  profile. Print a clear error if the id is missing. `login` with no args
  lists the ids present in the file (never the URLs).
- `update` — `git -C $REPO pull --ff-only --quiet`; skip silently on network
  failure (non-zero exit must not spam). If HEAD changed, or if `--force` is
  passed, run `install`. Never prompt.
- `list` — print the sites table (id, label, workspace, url).
- No subcommand or `help` — usage text.

Use `jq` for JSON (installed). Bash with `set -euo pipefail`. Keep the script
readable; it is the whole program.

## systemd user units

`lisa-launcher-update.timer`: `OnStartupSec=2min` (fires shortly after each
login, since the user manager starts at login) and `OnUnitActiveSec=1h`,
`Persistent=false`. Service is `Type=oneshot`, runs
`%h/.local/share/launcher-for-lisa/bin/lisa-launcher update`.

## `setup/create-account.sh` (one-off, root)

Run by the owner with sudo on this machine, and again only on a new machine.
Arguments: `--logins <file>` (required; the decoded login links to install),
`--repo <git url>` (default `https://github.com/vlebedev/launcher-for-lisa`).
Steps, each idempotent and printed as it runs:
1. `useradd -m -c "Elizaveta" -s /usr/bin/bash lisa` if missing (home is
   seeded from `/etc/skel`, which the `omarchy-settings` package owns; Omarchy
   self-provisions on her first Hyprland login via `omarchy-provision-first-run`).
   No extra groups: logind grants seat access. Not in `wheel` (no sudo).
2. `passwd lisa` interactively if the account has no password yet.
3. Enable `de_CH.UTF-8 UTF-8` in `/etc/locale.gen` and run `locale-gen` if not
   already generated (`localedef --list-archive` / `locale -a`).
4. Set her session language to `de_CH.UTF-8`: find how Omarchy/uwsm sessions
   pick up per-user environment (check `~/.config/environment.d/`,
   `~/.config/uwsm/env`, `/usr/share/omarchy/default/hypr/bootstrap.lua`,
   `omarchy-provision-user`) and use the mechanism that reaches both Hyprland
   and apps launched by the menu. Write `LANG=de_CH.UTF-8` there.
5. Keyboard: in `/home/lisa/.config/hypr/input.lua` set `kb_layout = "ch"`
   (Swiss German only) in the form the skel file uses. Check the skel file for
   the exact table shape.
6. Idle: in `/home/lisa/.config/omarchy/shell.json` set
   `idle.screensaver = 600`, `idle.lock = 3600` (jq in-place).
7. Remove SDDM autologin: move `/etc/sddm.conf.d/autologin.conf` to
   `/etc/sddm.conf.d/autologin.conf.disabled` if present. Print how to restore.
8. As `lisa`: clone `--repo` to `/home/lisa/.local/share/launcher-for-lisa`
   if absent (otherwise `git pull --ff-only`).
9. Install the logins file to `/home/lisa/.config/lisa-launcher/logins`,
   owner lisa, mode 600.
10. As `lisa`: run `bin/lisa-launcher install`.
11. Verify that Omarchy's first-run provisioning will not undo steps 4–6 or
    the `hyprland.lua` require: read `/usr/bin/omarchy-provision-user`,
    `/usr/bin/omarchy-provision-first-run` and
    `/usr/share/omarchy/install/user/first-run/*.sh`. If any step rewrites a
    file we touch, document it in the script header and work around it.
12. Omarchy migrations for a no-sudo account (decided 2026-09-10, option 3 of
    three considered). Migrations call `sudo` via an `as_root` helper that
    skips sudo when already root. Install `setup/lisa-omarchy-migrate` to
    `/usr/local/sbin/` (root, 0755) and a sudoers rule
    `lisa ALL=(root) NOPASSWD:SETENV: /usr/local/sbin/lisa-omarchy-migrate`
    (visudo-checked, 0440). The wrapper runs `/usr/bin/omarchy-migrate` as root
    with Lisa's HOME, USER, runtime dir, session bus, Wayland display and
    Hyprland signature, then re-owns anything root left in her home. Install
    `setup/omarchy-migrate-shim` as `~/.local/bin/omarchy-migrate` and put
    `~/.local/bin` first in her session PATH (environment.d and uwsm env.d),
    so the pending-migrations notification click and manual calls both go
    through the sudo path. Read-only `--pending` calls bypass sudo.
Everything that runs as `lisa` uses `sudo -u lisa -H` (or `runuser`).
Files under `/home/lisa` must end up owned by `lisa`.

## Owner workflow (README)

- Add a site: edit `sites.json`, `git commit`, `git push`. Within an hour, or at
  her next login, the menu and workspace rules update.
- Re-login to a site after a session expiry: as lisa, `lisa-launcher login <id>`.
- New machine: install Omarchy, then run `sudo setup/create-account.sh --logins <file>`.
- Restore autologin for the owner: move the `.disabled` file back.

## Things deliberately out of scope

Icons as images, native apps, lockdown/parental controls, a UI for editing
sites, private repo auth, testing inside Lisa's session (done manually by the
owner after first login).
